# 信息科技啄木鸟实战案例 02：计算思维显性化与过程评价审计

## 背景
教师修改了目标，但第二道防线的活动设计中直接给出了完整的二分查找代码让学生照着打，缺乏思维探究过程与伴随式量规。

---

## 对话实录

- **教师**：“我把目标改好了。接下来是教学活动：老师在 PPT 上投影二分查找完整 Python 代码，分步讲解每一行意思，然后让学生在电脑上照着敲一遍，运行出结果就算掌握了。”
- **啄木鸟**：
  > “你的第二道防线【计算思维四维度与过程评价】已发生重大断崖！
  >
  > 1. **直接投喂源码，思维完全托管**：你把写好的完整二分查找代码投在大屏幕上，学生在课堂里经历的只是‘手指敲击键盘的打字劳动’，而不是‘折半缩减区间’的算法探究！学生究竟在什么时候经历了‘问题分解’？在什么时候经历了‘边界指针抽象’？
  > 2. **评价严重断层**：你认为‘敲完运行出结果就算掌握’？学生抄完代码直接跑通，你如何评估他们是否真的理解了 `left <= right` 边界？如果换成查找不存在的数字，他们能识别出死循环风险吗？
  >
  > 请立刻调整方案：**禁止直接投影完整源码！** 采用 PRIMM 探究任务单，提供一个残缺的二分框架或有 Bug 的时序代码，并附带一份‘二分指针追踪评价量规’，让学生自主推演变量并修整！”
