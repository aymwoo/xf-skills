# 计算思维学科本体与四维模型 (Computational Thinking Dimensions)

## 1. 核心定义
计算思维（Jeannette Wing, 2006）是运用计算机科学的基础概念进行问题求解、系统设计以及人类行为理解的涵盖面极广的思维活动。

## 2. 计算思维四维操作模型

```
┌─────────────────────────────────────────────────────────────┐
│                    计算思维 (Computational Thinking)          │
├─────────────────┬─────────────────┬─────────────────────────┤
│ 1. 分解         │ 2. 模式识别     │ 3. 抽象                 │ 4. 算法设计
│ (Decomposition) │ (Pattern Recog) │ (Abstraction)           │ (Algorithm)
├─────────────────┼─────────────────┼─────────────────────────┤
│ 将庞大复杂问题   │ 寻找数据或问题中│ 忽略次要与偶发细节，    │ 设计清晰、明确、
│ 拆分为若干独立、 │ 的规律、重复性与│ 提取关键核心本质，建构  │ 有穷可执行的步骤
│ 易于解决的子模块 │ 历史相似特征    │ 数学或数据模型          │ 规则与程序逻辑
└─────────────────┴─────────────────┴─────────────────────────┘
```

## 3. 常见学生认知误区与教学纠偏

| 典型误区 | 现象描述 | 纠偏策略 |
| :--- | :--- | :--- |
| **代码即思维** | 以为只要死记硬背 Python 语法就是掌握了计算思维 | 开展无电脑脱机活动（Unplugged），先手绘流程图再编码 |
| **忽视边界** | 编写循环或递归时不考虑终止条件导致死循环或栈溢出 | 引入边界极端测试用例（如 0、空数组、负数） |
| **缺乏模块化** | 将几百行代码全写在同一个全局作用域中 | 引导使用函数与类进行封装和参数传递 |
